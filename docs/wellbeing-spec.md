# Техническое задание на раздел Моё состояние

Дата: 1 октября 2026 года. Статус: проект ТЗ по согласованному макету.

Раздел хранит дневные записи физического и психоэмоционального состояния и показывает выполнение личных ориентиров пользователя. Индикатор не является медицинской оценкой, нормой безопасности употребления или доказательством эффективности работы.

Визуальный образец: [финальный макет](mockups/wellbeing.html). [Редактируемый исходник](mockups/wellbeing.fragment.html) сохранён без изменений. Связанные документы: [карточка задачи](task-card-spec.md), [статистика](statistics-spec.md), [рабочий день](workday-spec.md).

Общий контракт сущностей, связей и открытых решений: [каркас проекта](project-spec.md). Он уточняет межраздельные инварианты; решения с отметкой `proposal` не становятся утверждёнными требованиями.

## 1. Состав экрана

Сохранить общую навигацию Spotter, дату записи и компактные значки источников. Основной развёрнутый блок — «День по моим ориентирам» с тремя вложенными кольцами и пояснениями значений.

Ниже, в указанном порядке, свёрнутые по умолчанию блоки:

1. Сон и активность.
2. Самочувствие.
3. Вредные привычки.
4. Физические измерения.

Внизу — сохранение записи дня и сообщение о результате. В заголовках свёрнутых блоков допустимы короткие сводки. Не добавлять отдельные блоки динамики, источников, наблюдений и нагрузки за день: пользователь исключил их из текущего экрана. Не включать привязку заметки самочувствия к конкретной задаче.

Источник обозначается значком с доступным названием, состоянием и подсказкой. Например, ручной ввод доступен, iPhone не подключён. Наличие значка не должно означать успешную интеграцию. Подробная диагностика раскрывается по нажатию, не занимает постоянный блок.

## 2. Поля дневной записи

### Сон и активность

- Продолжительность сна в часах; конечное неотрицательное число, разрешить дробное значение. Пустое поле означает отсутствие записи, подтверждённый 0 — отсутствие сна, это разные состояния.
- Число шагов, неотрицательное целое.
- Для обоих полей хранить источник и дату/время актуальности. Отсутствие данных не равно нулю.

Сон относится к дате пробуждения в часовом поясе пользователя. Для пересекающихся импортированных интервалов не считать время дважды. Если доступен только существующий агрегат сна за окно перед экспортом, хранить границы этого окна и не выдавать его за точную ночную длительность без соответствующих данных.

### Самочувствие

- Настроение: не отмечено, тяжёлое, ниже обычного, обычное, хорошее, отличное.
- Энергия: не отмечено, очень мало, мало, средняя, много.
- Ощущаемый стресс: не отмечено, низкий, умеренный, высокий.
- Общая заметка дня, многострочный текст.

Значения формы по умолчанию: обычное настроение, средняя энергия, низкий стресс. Это удобство ввода, а не автоматически зарегистрированное наблюдение. Предусмотреть признак явного подтверждения пользователем и время подтверждения. Вариант «не отмечено» остаётся отсутствием данных даже после сохранения других полей.

### Вредные привычки

Два неотрицательных целочисленных счётчика: сигареты за день и условные порции алкоголя за день. Значение формы по умолчанию — 0 для каждого.

Одна условная порция в пользовательской модели — бокал пива, бокал вина или рюмка крепкого алкоголя. Не запрашивать название напитка, объём и крепость. Не пересчитывать эти порции в массу спирта и не заявлять одинаковую дозу для разных напитков.

0 означает «не употреблялось», но становится записью только после подтверждения/сохранения. Пустой день в истории не заполняется нулями автоматически. Смена даты и открытие страницы не подтверждают значения.

### Физические измерения

Хранить отдельные записи, а не одно смешанное среднее:

- Пульс, уд/мин; тип: разовое измерение, в покое, средний за день.
- Частота дыхания, дыхательных циклов/мин.
- Насыщение крови кислородом, %.
- Температура, °C.
- Давление: систолическое и диастолическое, мм рт. ст.
- Глюкоза с явной единицей: ммоль/л или мг/дл.

Каждое измерение имеет ID, время, источник и единицу. Для среднего значения сохранять период агрегации. Не смешивать пульс в покое и средний за день. Не выполнять скрытую конверсию единиц и не выдавать клинические заключения. Валидировать формат, конечность числа и согласованные технические пределы; не вводить произвольные «медицинские нормы» для цвета.

## 3. Геометрия индикатора

Три концентрических кольца, без текста в центре:

- Внешнее — вредные привычки.
- Среднее — активность.
- Внутреннее — сон и самочувствие.

Сохранить компактный размер последнего макета. Точный ориентир: SVG viewBox 220 × 220, отображение 176 × 176 CSS px; центр 110/110; радиусы 91, 55 и 19; толщина дуги 18 единиц viewBox. Расстояние между видимыми краями соседних колец равно толщине кольца: 18 единиц. При масштабе 0,8 толщина и зазор равны 14,4 CSS px, видимый внешний диаметр — 160 CSS px; 176 px — размер SVG с полями, а не диаметр внешнего кольца. Внешняя граница остаётся прежней при настройке внутренней геометрии.

При масштабировании пропорции, толщина и промежутки сохраняются. Дуги начинаются сверху и заполняются по часовой стрелке. Фон незаполненной части нейтральный, цвет текста доступен в светлой и тёмной теме. Полное кольцо не должно показывать стык или выходить за SVG.

Не полагаться только на цвет: рядом выводить название ориентира, исходные значения, степень выполнения/категорию и отсутствие подтверждения. Кольца не складываются в общий процент или балл.

## 4. Внешнее кольцо вредных привычек

Кольцо всегда полностью заполнено и меняет только цвет. Пусть C — подтверждённое число сигарет, A — подтверждённое число условных порций алкоголя.

| Условие | Цвет |
|---|---|
| C = 0 и A = 0 | Зелёный |
| Не 0/0, при этом C ≤ 5 и A ≤ 2 | Жёлтый |
| Зелёное/жёлтое условие не выполнено, но C ≤ 10 и A ≤ 4 | Оранжевый |
| C > 10 или A > 4 | Красный |
| Значения отсутствуют или не подтверждены | Нейтральный серый |

Проверять от наиболее строгого превышения либо в порядке таблицы без пересечений. Худшее значение определяет категорию: 0 сигарет и 5 порций — красный, 6 сигарет и 0 порций — оранжевый. Любое ненулевое значение исключает зелёный.

Именно эта шкала заменяет ранний вариант «до 5/2 — зелёный». Подпись должна ясно говорить о личных пользовательских порогах, а не о безопасных уровнях употребления.

## 5. Среднее кольцо активности

Активная дуга всегда зелёная; меняется только заполнение. Использовать альтернативные способы достижения цели:

- 10 000 шагов;
- 3 сложные завершённые задачи;
- 5 средних завершённых задач;
- 7 простых завершённых задач.

Формула для имеющихся данных:

    P = min(1, max(steps / 10000, hardDone / 3, mediumDone / 5, easyDone / 7))

Вычислять максимум только по известным значениям: отсутствие шагов не создаёт аргумент steps=0. Данные всех трёх категорий задач поступают одним агрегатом с признаком полноты. Ноль задач достоверен при доступной полной истории нужного дня; сбой запроса или дата до начала учёта означает неизвестные данные. Неизвестный источник не подставляется как достоверный ноль. Если есть хотя бы один доступный источник, показать подтверждённый прогресс по нему и отметить частичность данных. Если нет ни одного — только нейтральная дорожка и «Нет данных».

Шаги и задачи не складываются. Смешанная сложность тоже пока не складывается: 2 сложные и 2 средние дают max(2/3, 2/5), а не полную цель. Это выбранная для макета трактовка, которую нужно явно показать в раскрытии формулы; иной алгоритм смешивания требует согласования.

Дуга растёт по мере появления шагов и завершённых задач. Не увеличивать её просто от течения времени, запущенного таймера или частичного выполнения подпунктов. Итог ограничен 100%. Коррекция шагов или повторное открытие задачи может уменьшить прогресс; индикатор не фиксирует однажды достигнутый максимум навсегда.

## 6. Сложность и учёт задач

Добавить в общую карточку задачи поле сложности: простая, средняя, сложная. По умолчанию — средняя. Это пользовательская категория, независимая от оценки минут, важности и количества подпунктов. Не определять её автоматически из длительности без отдельного решения.

Считать уникальные завершённые задачи и конкретные выполнения регулярных задач за выбранную календарную дату. Повторные нажатия, версии плана и подпункты не добавляют отдельные завершения. Завершение вне плана учитывается на общих основаниях.

Задачи с отметкой «выполнено другим человеком» не считать умственной активностью владельца дневника. Повторное открытие корректирует число по правилам статистики. Для текущей даты использовать актуальное состояние; для исторической — предлагается расчёт состояния на границу выбранного дня. Это применение общего алгоритма статистики к периоду длиной один день, а не копирование дневного столбца месячного отчёта: там границей расчёта может быть конец месяца. Например, завершение 1 октября и открытие 2 октября оставляют исторический результат 1 октября, но могут исключать задачу из месячного итога на 2 октября. Это различие необходимо явно согласовать и объяснить в деталях; не обещать тождество дневника и столбца отчёта с другой границей расчёта.

Предлагается фиксировать сложность на момент завершения в событии. Поздняя правка сложности не переписывает прошлый показатель без явной корректировки истории. Миграция существующих задач назначает среднюю сложность, но не создаёт выдуманные даты завершения.

В конечном продукте числа поступают из задач, не вводятся вручную в дневнике. Поля числа простых/средних/сложных задач в макете — только демонстрационные регуляторы и в рабочем интерфейсе не нужны.

## 7. Внутреннее кольцо сна и самочувствия

Заполнение определяется только длительностью сна:

    S = min(1, sleepHours / 7)

Сон 3,5 часа даёт половину дуги, 7 и более — полную. Не увеличивать заполнение за сон сверх цели. Если сон отсутствует, показывать нейтральную дорожку и подпись «Нет данных о сне».

Цвет определяется только подтверждёнными настроением, энергией и стрессом, независимо от длительности сна. Следующая шкала была предложена в макете; точную раскладку эмоциональных уровней следует подтвердить перед реализацией:

| Компонент | Зелёный 0 | Жёлтый 1 | Оранжевый 2 | Красный 3 |
|---|---|---|---|---|
| Настроение | Обычное, хорошее, отличное | Ниже обычного | — | Тяжёлое |
| Энергия | Средняя, много | Мало | — | Очень мало |
| Стресс | Низкий | — | Умеренный | Высокий |

Выбирать максимальный индекс из трёх компонентов. Если часть самочувствия не отмечена/не подтверждена, дуга сна остаётся соответствующей длительности, но её цвет серый с пояснением. Отсутствие данных не красная зона.

Примеры: 3,5 часа и обычное самочувствие — половина зелёной дуги; 8 часов и высокий стресс — полная красная дуга. При нулевом заполнении цвет самочувствия должен оставаться доступен в текстовой подписи.

## 8. Сохранение и даты

Дневная запись идентифицируется датой и сохранённым часовым поясом пользователя (IANA). Смена пояса в настройках не перемещает и не дублирует уже сохранённые ручные дневные записи; показывать исходный пояс записи. Правило пересчёта импортированных измерений и задач должно использовать тот же сохранённый пояс при восстановлении этого дня. Даты измерений хранятся как абсолютное время с исходным смещением/поясом, а не как неоднозначная строка локального времени. Сохранять исходные временные отметки импортов и измерений. Смена даты не должна переносить сон, подтверждение, привычки или заметку в другой день.

Явное сохранение может одновременно подтверждать стандартные значения самочувствия и счётчики вредных привычек; перед кнопкой это понятно обозначается. Для частичного заполнения дать отдельные переключатели подтверждения групп: сохранение одного физического измерения не должно незаметно подтверждать нормальное самочувствие и 0/0. Явная кнопка «Подтвердить стандартные значения и сохранить» может подтверждать обе группы сразу. До подтверждения кольца используют сохранённые/подтверждённые значения, а предварительный расчёт по черновику, если показывается, явно подписан как предварительный. Хранить отдельные признаки полноты/подтверждения для групп. Изменение подтверждённого поля создаёт черновик, а не меняет сохранённую запись без команды.

При смене даты с изменениями обеспечить сохранение черновика либо явное предложение сохранить/отменить. Повторное открытие восстанавливает сохранённые данные. Ошибка записи не должна давать сообщение об успехе. Конфликт версий сохраняет ввод и не перезаписывает чужие изменения автоматически.

## 9. Источники и интеграции

Первая версия должна полноценно поддерживать ручной ввод. В текущем проекте предусмотрен мост импорта сна; другие показатели требуют отдельной интеграции. Не заявлять наличие HealthKit или полной синхронизации iPhone без реализации и проверки на устройстве.

Подготовить расширяемый контракт источника: тип показателя, значение, единица, время/интервал, ID источника/образца, время получения и качество/полнота. Повторный импорт не создаёт дубли; повтор сохранения ручного измерения после потери ответа также идемпотентен по ID операции/измерения. При нескольких устройствах и пересекающихся выборках не суммировать шаги/сон без правил разрешения перекрытий.

Импорт не перезаписывает ручную правку молча. Сохранять происхождение и различать исходное измерение и пользовательскую коррекцию. Недоступный источник помечается недоступным, а не возвращает нули.

У каждого поля доступно происхождение через компактный значок/подсказку, даже если общая интеграция подключена: значок подключения не заменяет источник конкретного значения.

Состояние хранится локально отдельно от модельных выжимок. Дневник, заметки и измерения не отправляются модели или внешней аналитике в рамках этого ТЗ. Не включать личное содержимое в диагностические логи; резервное копирование и миграция должны сохранять историю без публикации.

## 10. Техническая модель

Предусмотреть DayWellbeingRecord, Measurement, SourceMetadata и конфигурацию личных ориентиров либо эквивалентные структуры. Разделить значения, подтверждение, единицы, источник и время. Исторические измерения не сводить к одному изменяемому агрегату.

Расчёт колец реализовать чистой детерминированной функцией с результатом для каждой дуги: доля заполнения, цветовая категория, полнота данных, исходные значения и причины. Сервер и клиент используют одинаковый контракт и проверочные примеры; при разных языках реализация может быть разной, но ответы по одинаковым данным должны совпадать. Для статистики задач возвращать дату, часовой пояс и границу расчёта, чтобы кольцо не смешивало разные периоды.

Сохранить существующие оптимистические версии workspace, серверную валидацию, Origin и защитный заголовок. Миграция совместима с уже сохранённым сном и настройками. Перед изменением схемы создать резервную копию. Предыдущая личная цель сна в настройках не сбрасывается молча: 7 часов здесь — отдельный ориентир индикатора, его связь с прежней настройкой нужно явно определить.

Изменение конфигурации ориентиров в будущем должно иметь версию, чтобы было понятно, по каким правилам рассчитан прошлый день. В текущем объёме интерфейс редактирования всех порогов не обязателен.

## 11. Ограничения демонстрации и отложенное

Макет сохраняет записи только в памяти страницы; реальная долговечность, импорт и восстановление не реализованы. В нём используются пример задач за одну дату и ручные регуляторы сложности. Не переносить эти заглушки в продукт.

Не реализуются в данном этапе: корреляционный анализ, медицинские рекомендации, графики длительной динамики, связь заметки с отдельной задачей, отдельные блоки нагрузки и наблюдений. Историю сохранять так, чтобы последующее исследование связей по датам было возможно; совпадение показателей не трактовать как причинность.

Перед разработкой уточнить предложенную шкалу самочувствия, трактовку смешанной сложности задач и связь 7-часового ориентира с существующей персональной целью сна. Также согласовать описанную границу исторических завершений; в проверенном макете частичное подтверждение представлено двумя независимыми переключателями. Остальные пороги и геометрия соответствуют последним уточнениям пользователя.

## 12. Критерии приёмки

1. На экране только согласованные блоки в нужном порядке; источники представлены компактными доступными значками.
2. Сон/активность, самочувствие, вредные привычки и измерения свёрнуты при открытии, индикатор открыт. В центре колец нет текста.
3. Промежуток между соседними кольцами равен их толщине, порядок колец и внешний диаметр соответствуют макету.
4. Внешнее кольцо всегда полное. Проверены пары 0/0, 1/0, 0/1, 5/2, 6/2, 10/4, 11/0, 0/5 и неподтверждённые значения.
5. Средняя активная дуга всегда зелёная; 5000 шагов дают 50%, 10000 — 100%; альтернативные цели задач работают без сложения категорий.
6. При 3,5 часа сна заполнение внутренней дуги 50% независимо от стресса; цвет зависит от самочувствия, а не от часов.
7. Пустые/неподтверждённые поля не считаются успешным днём автоматически. Дефолтные 0/0 не превращаются в исторические записи при открытии даты.
8. Сложность задачи по умолчанию средняя, изменяется в общей карточке. Чужая работа, подпункты и повторные события не увеличивают личную активность.
9. Каждое физическое измерение сохраняет время, источник и единицу; давление содержит оба значения, глюкоза не смешивает единицы.
10. Смена даты, обновление страницы, ошибка записи и конфликт вкладок не теряют сохранённые данные или черновик незаметно.
11. Отсутствие источника не даёт ноль, повторный импорт не дублирует данные, ручная коррекция не затирается молча.
12. Доступны текстовые пояснения цветов и значений, клавиатура и узкий экран. Медицинские выводы и утверждения о безопасности употребления отсутствуют.

13. Сохранение только физического измерения не подтверждает автоматически дефолты самочувствия и вредных привычек; частичность объясняется рядом с кольцами.
14. Проверены отсутствие шагов при известных задачах, известные нули и недоступная история; уменьшение прогресса при коррекции не блокируется.
15. Смена часового пояса не создаёт дубли дневных записей; измерения и задачи агрегируются в пояс выбранной записи.
16. Завершение и повторное открытие в разные дни проверены с явно указанной границей расчёта; повтор ручной записи после потери ответа не создаёт дубль.

## 13. План реализации и проверки

Сначала согласовать общий контракт дневной записи и историю сложности задач, затем реализовать хранение/миграцию, расчёт колец, формы и доступную визуализацию. Подключение реальных источников выполнять отдельными проверяемыми адаптерами.

Тесты: все граничные пороги, неизвестные данные, подтверждение и дефолты, расчёт альтернативной активности, независимость цвета и заполнения сна, повторное открытие задач, временные зоны, миграция сна, конфликты и дедупликация импорта.

Браузерная проверка: сворачивание, смена даты, ошибки в скрытых полях, кольца в обеих темах, доступность значков, чтение значений без различения цвета. Выполнить применимые Go/frontend-проверки из README. Реальный импорт с iPhone и физические показания требуют отдельного подтверждения; тесты на примерах этого не доказывают.

## 14. Соответствие проверенному макету

В образце совпадают окончательные порядок и геометрия колец (91/55/19, толщина 18, SVG 176 px), четыре зоны вредных привычек с отдельным 0/0, зелёное заполнение активности, независимость цвета самочувствия и заполнения сна. Самочувствие и вредные привычки подтверждаются раздельно; один переключатель не подтверждает другую группу. Кольца показывают предварительный расчёт по черновику с явной подписью, сохранение применяется отдельно. Рядом с цветами показаны названия категорий и проценты заполнения, включая отсутствие данных.

Не реализованы образцом и остаются обязательными требованиями продукта: долговечное хранение, timestamp подтверждения каждой группы, источники каждого показателя, ID и структурированные значения измерений, импорт/дедупликация, реальная агрегация задач с учётом исполнителя/истории/сложности, конфликт версий и общая конфигурация часовых поясов. Регуляторы задач в образце — демонстрация одной даты. Семантика границы исторических завершений с разделом статистики остаётся открытым решением, а не исправлением данных в пользу одного экрана.

Миграционная «Средняя» относится к текущей задаче, не к неизвестной сложности старого завершения. Исторические завершения без категории не распределять по средним: показывать неполноту данных задач для кольца. Рабочий дневник и отчёт обязаны возвращать свою границу расчёта и пояс/IANA вместе с показателями.
