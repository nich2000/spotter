# Соответствие рабочего дня — этап 3

| Требование | Макет / результат проверки |
|---|---|
| Навигация, дата, фокус и Pomodoro | Представлены, компоновка сохранена |
| Выбор фокуса отдельно от таймера | Работает; атрибуция серверных сессий ещё требуется |
| Возврат из фона/ожидания | Исправлено: старая проверка больше не отображается действующей, прежние сведения сохраняются в demo-записи |
| Состояния доски и повторное открытие | Работают; `focus` в demo остаётся упрощением общей lifecycle/workMode модели |
| Неизвестная трудоёмкость | Исправлено: не считается короткой/нулём, принимается при перепланировании, бюджет обозначает неполноту |
| Бюджет с календарём/перерывами | Демонстрационный пример явно подписан; полный расчёт требуется реализации, не заявляется готовым |
| Снимок до перехода к новому плану | Исправлен порядок: копия сохраняется до снятия фокуса; незавершённое сохраняет состояния |
| Другая дата нового плана | Требуется реализации, ограничение текущего demo указано рядом с подбором |
| Главный результат/лягушка, общий редактор | Требуется реализации; требования ТЗ сохранены |
| Повторения без дублей | Demo содержит подписи примеров, не scheduler; backend/дедупликация требуют реализации |
| Долговечность, версии, миграция, конкурентность | Требуется реализации; widgetState не объявлен эквивалентом рабочего хранения |

В ТЗ добавлена явная граница образца: пробелы не становятся исключениями из согласованного объёма. Исправлено устаревшее упоминание 240-минутного порога многодневности. Сохранены открытые решения о лимитах, длинном перерыве, независимом таймере и нескольких датах плана.

Browser: workday-browser.cjs и workday-alignment.cjs прошли в Chrome на прямом fragment. Второй тест проверяет прекращение старой проверки при фокусе и неизвестную оценку при новом плане. Первый — существующие статусы, подпункты, перепланирование, 320px и runtime. Оболочка экспорта не является доказанной браузерной поверхностью этих тестов. HTML regenerated штатным render.py.
