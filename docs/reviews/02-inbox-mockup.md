# Inbox: проверка интерактивного макета

Исправлены `inbox.fragment.html` и заново сформирован `inbox.html` штатным render.py.

## Найдено и исправлено

- Возврат в неразобранное удалял включение в план и терял приоритет. Теперь разбор — отдельный признак, план сохраняется.
- Сохранение внешнего предложения без квадранта не принимало его; исправлено.
- Действия редактора применялись немедленно и терялись несохранённые изменения. Используется черновик и явное подтверждение отказа от изменений. Браузерный confirm не работает в sandbox, заменён вторым явным нажатием «Отбросить изменения».
- Кнопка ⋯ больше не дублирует название: отдельные действия, классификация, план, завершение и восстановление без копии.
- Диалог ограничен по ширине, возврат фокуса и клавиатурный Escape; интерактивная зона ⋯ расширена для касания.
- Восстановление state проверяет ID, числовые значения и уникальность; устаревшие обратные события host больше не затирают только что изменённые записи (ревизия снимка).
- Отсутствующий объём времени остаётся неизвестным. Состояние не передаёт текст личных задач в modelContent.

## Границы

Демонстрационный редактор показывает основные поля, не полную согласованную карточку; её интеграция проверяется отдельно на этапе соответствия ТЗ. Нет серверной синхронизации, реальных источников, таймера и общего хранилища между независимыми макетами. Сохранение state ограничено размером; превышение показывается, а не обещает сохранение. Production-дедупликация и атомарность не имитируются.

Дополнительная граница браузерной проверки: после многократной смены viewport Chromium/экспортный iframe не доставил pointer-click в документ (проверено capture-listener: событий нет). Поэтому открытие мобильного диалога проверяется Enter, а успешный touch-click не заявляется. Полная проверка touch остаётся для этапа соответствия/целевого контейнера.
